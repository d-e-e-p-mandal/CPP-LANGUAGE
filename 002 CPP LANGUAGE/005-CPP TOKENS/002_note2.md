# 5.1 Token Types

## 5.1.1 What Is a Token?

A **token** is a basic lexical unit recognized by the C++ compiler.

A C++ source file is written as a sequence of characters. During lexical processing, those characters are grouped into meaningful units.

For example:

```cpp
int age = 25;
```

can be viewed as:

```text
int    age    =    25    ;
│      │      │    │     │
│      │      │    │     └── punctuator
│      │      │    └──────── literal
│      │      └───────────── operator
│      └──────────────────── identifier
└─────────────────────────── keyword
```

A useful simplified model is:

```text
C++ source
    |
    v
characters
    |
    v
lexical analysis
    |
    v
tokens
    |
    +--> keywords
    +--> identifiers
    +--> literals
    +--> operators
    +--> punctuators
```

### Important terminology

Do not confuse:

- **Character** — an individual source character.
- **Lexeme** — the sequence of source characters that forms a lexical unit.
- **Token** — the lexical category/meaning assigned to that unit.

For example:

```cpp
int count = 10;
```

The text:

```text
count
```

is a lexeme that represents an **identifier token**.

The text:

```text
10
```

is a lexeme that represents an **integer literal token**.

---

## 5.1.2 Keywords

Keywords are words reserved by the C++ language and have predefined syntactic meaning.

Examples:

```cpp
int
class
if
else
return
for
while
template
```

You cannot normally declare:

```cpp
int class = 10;    // Error
```

because `class` already has a language-defined meaning.

---

## 5.1.3 Identifiers

Identifiers are names used by the programmer.

Examples:

```cpp
age
studentName
Employee
calculateTotal
```

Example:

```cpp
int studentAge = 20;

void printStudent()
{
}
```

Here:

```text
studentAge   -> identifier
printStudent -> identifier
```

Identifiers can name many kinds of entities:

- Variables
- Functions
- Classes
- Structs
- Unions
- Enumerators
- Namespaces
- Templates
- Data members
- Member functions
- Type aliases
- Concepts
- Other declarations

---

## 5.1.4 Literals

A literal is a value written directly in the source code.

Examples:

```cpp
10
3.14
'A'
"Hello"
true
false
nullptr
```

Common literal categories are:

| Literal | Example |
|---|---|
| Integer | `10`, `42`, `0xff` |
| Floating-point | `3.14`, `1.0e10` |
| Character | `'A'`, `'\n'` |
| String | `"Hello"` |
| Boolean | `true`, `false` |
| Null pointer | `nullptr` |
| User-defined | `42_km`, `3.14_deg` |

Example:

```cpp
int age = 25;
double price = 99.99;
char grade = 'A';
bool active = true;
const char* name = "Deep";
int* ptr = nullptr;
```

### Literal vs identifier

These are different:

```cpp
int age = 25;
```

```text
age -> identifier
25  -> literal
```

`age` names an object, while `25` directly represents a value.

## 5.1.6 Punctuators

Punctuators are lexical symbols that provide syntactic structure.

Important examples include:

```text
;
,
.
->
::
:
?
()
[]
{}
<>
```

Some symbols can have different roles depending on context.

For example:

```cpp

&

-
<
>
```

---

## 5.1.7 Tokenization Example

Consider:

```cpp
int total = count + 10;
```

Tokenized conceptually:

| Source | Category |
|---|---|
| `int` | Keyword |
| `total` | Identifier |
| `=` | Operator |
| `count` | Identifier |
| `+` | Operator |
| `10` | Integer literal |
| `;` | Punctuator |

Another example:

```cpp
std::cout << "Hello";
```

| Source | Category |
|---|---|
| `std` | Identifier/name |
| `::` | Punctuator |
| `cout` | Identifier/name |
| `<<` | Operator |
| `"Hello"` | String literal |
| `;` | Punctuator |

# 5.2 Identifiers

An **identifier** is a name introduced by a C++ program.

Example:

```cpp
int age;
```

Here:

```text
age
```

is an identifier.

More examples:

```cpp
int count;
double totalPrice;

void calculateTotal();

class Student;

namespace Company;
```

Identifiers make source code understandable because they allow programmers to give names to program entities.

---

# 5.2.1 Identifier Rules

The basic identifier rules are:

1. An identifier can contain letters.
2. An identifier can contain digits.
3. An identifier can contain underscores.
4. An identifier cannot begin with a digit.
5. An identifier cannot normally be a keyword.
6. C++ identifiers are case-sensitive.
7. Certain names are reserved to the implementation.

### Valid examples

```cpp
age
age1
student2
student_name
_total
MyClass
calculateTotal
value123
```

### Invalid examples

```cpp
2age             // Starts with a digit
student-name     // '-' is not permitted in an identifier
student name     // Space is not permitted
class            // Keyword
```

---

# 5.2.2 Identifier Grammar

A simplified mental model is:

```text
identifier
    |
    +-- first character
    |      |
    |      +-- letter
    |      +-- underscore
    |
    +-- following characters
           |
           +-- letters
           +-- digits
           +-- underscores
```

For ordinary ASCII-style identifiers:

```text
first:
    A-Z
    a-z
    _

following:
    A-Z
    a-z
    0-9
    _
```

Therefore:

```cpp
employee1
```

is valid because the first character is `e`, and the digit `1` appears later.

But:

```cpp
1employee
```

is invalid because the first character is a digit.

### Important

The exact C++ lexical grammar is more general than this simplified ASCII explanation and supports implementation-defined character sets and Unicode-related identifiers. For everyday code, the simplified rules are useful.

---

# 5.2.3 Naming Rules and Conventions

There is an important difference between:

### Language rules

These are enforced by the compiler.

Example:

```cpp
int 123value = 10;   // Invalid
```

### Naming conventions

These are style decisions made by programmers or projects.

For example, all of these can be valid:

```cpp
int studentAge;
int student_age;
int StudentAge;
```

A project may select one style.

---

## Common naming styles

### camelCase

Usually starts with a lowercase letter and capitalizes later words.

```cpp
int studentAge;
double totalAmount;

void calculateTotal();
```

### PascalCase

Usually capitalizes each word.

```cpp
class StudentRecord
{
};

class EmployeeManager
{
};
```

### snake_case

Words are separated with underscores.

```cpp
int student_age;
double total_amount;

void calculate_total();
```

### UPPER_CASE

Commonly seen in macros and some older codebases:

```cpp
#define MAX_SIZE 100
```

For modern C++ constants, prefer meaningful typed constants such as:

```cpp
constexpr int maxSize = 100;
```

rather than using a macro simply to define a constant.

---

## Good naming principles

### 1. Use meaningful names

Prefer:

```cpp
int studentCount;
```

over:

```cpp
int x;
```

when the purpose is student count.

### 2. Use names that match the entity

```cpp
class Customer;
void calculateSalary();
bool isActive;
```

### 3. Avoid unnecessary abbreviations

Prefer:

```cpp
customerAddress
```

over:

```cpp
custAddr
```

unless the abbreviation is well established in the project.

### 4. Be consistent

Do not mix styles randomly:

```cpp
studentAge
student_name
StudentAddress
```

A consistent codebase is easier to maintain.

---

# 5.2.4 Case Sensitivity

C++ is **case-sensitive**.

Therefore:

```cpp
value
Value
VALUE
vAlUe
```

are different identifiers.

Example:

```cpp
int value = 10;
int Value = 20;

std::cout << value << '\n';
std::cout << Value << '\n';
```

Output:

```text
10
20
```

The compiler treats `value` and `Value` as separate names.

### Common mistake

This is not the same variable:

```cpp
int studentAge = 20;

std::cout << studentage; // Error: different spelling
```

The correct name is:

```cpp
studentAge
```

---

# 5.2.5 Keywords Cannot Normally Be Identifiers

Keywords already have language-defined meaning.

This is invalid:

```cpp
int return = 10;
```

This is also invalid:

```cpp
int class = 20;
```

But a keyword can be part of a larger identifier:

```cpp
int returnValue = 10;
int classCount = 20;
```

These are valid because the complete names are:

```text
returnValue
classCount
```

not:

```text
return
class
```

---

# 5.2.6 Reserved Identifiers

C++ reserves certain identifier forms for the implementation and standard library.

This is an important topic because using reserved names can make a program ill-formed or lead to undefined behavior.

## Double underscore

Avoid identifiers containing two consecutive underscores:

```cpp
__value
my__value
```

Such names are reserved to the implementation.

## Leading underscore followed by uppercase letter

Avoid:

```cpp
_Foo
_Bar
```

These names are reserved in important contexts.

## Leading underscore at global/namespace scope

Avoid names such as:

```cpp
_value
```

at global/namespace scope because such names are reserved to the implementation.

### Safe practical rule

For normal application code:

> **Do not start your own identifiers with `_`, and never use `__` in an identifier.**

Prefer:

```cpp
int employeeCount;
```

instead of:

```cpp
int _employeeCount;
int __employeeCount;
```

### Important distinction

Not every identifier containing an underscore is reserved.

These are ordinary examples:

```cpp
student_name
employee_count
calculate_total
```

The problem is primarily the reserved naming patterns defined by the language.

---

# 5.2.7 Scope, Linkage, and Identifier Names

Identifier syntax and identifier scope are different concepts.

Consider:

```cpp
int value = 100;

void test()
{
    int value = 200;

    std::cout << value;
}
```

There are two identifiers spelled:

```text
value
```

but they refer to different objects because they belong to different scopes.

The local variable hides the global variable inside `test`.

You can access the global object with:

```cpp
std::cout << ::value;
```

### Scope

Scope determines where a name can be used.

Common scopes include:

- Block scope
- Function parameter scope
- Class scope
- Namespace scope
- Global scope

### Linkage

Linkage determines whether declarations in different scopes or translation units can refer to the same entity.

This is a deeper topic than tokenization, but it is useful to understand that:

```text
identifier spelling
```

does not by itself determine which entity a name refers to.

---

# 5.2.8 Unicode Identifiers

Modern C++ source code can contain identifiers using characters beyond simple ASCII, subject to the C++ lexical rules and implementation support.

For example, source code may use Unicode characters in identifiers.

However, for portable and maintainable production code, many projects prefer a restricted ASCII naming convention:

```cpp
int studentCount;
```

rather than relying on visually similar Unicode characters.

### Why?

Unicode identifiers can introduce:

- Readability issues
- Confusable characters
- Tooling differences
- Encoding concerns
- Maintenance difficulties

Therefore, follow the coding standard of your project.

# 5.3.4 Control-Flow Keywords

Control-flow keywords affect the execution path.

Important keywords:

```text
if
else
switch
case
default
for
while
do
break
continue
goto
return
```

---

## `if`

Executes code conditionally.

```cpp
if (age >= 18)
{
    std::cout << "Adult";
}
```

---

## `else`

Provides an alternative branch.

```cpp
if (age >= 18)
{
    std::cout << "Adult";
}
else
{
    std::cout << "Minor";
}
```

---

## `else if`

Multiple conditions can be tested:

```cpp
if (marks >= 90)
{
    std::cout << "A";
}
else if (marks >= 75)
{
    std::cout << "B";
}
else
{
    std::cout << "C";
}
```

`else if` is not one single keyword. It is:

```text
else + if
```

---

## `switch`

Selects among cases.

```cpp
switch (choice)
{
    case 1:
        std::cout << "One";
        break;

    case 2:
        std::cout << "Two";
        break;

    default:
        std::cout << "Other";
        break;
}
```

---

## `case`

Defines a switch case:

```cpp
case 1:
```

---

## `default`

Provides the fallback switch case:

```cpp
default:
```

---

## `for`

A loop with initialization, condition, and iteration expression:

```cpp
for (int i = 0; i < 10; ++i)
{
    std::cout << i;
}
```

---

## `while`

Repeats while the condition is true:

```cpp
while (count < 10)
{
    ++count;
}
```

---

## `do`

Runs the body before checking the condition:

```cpp
do
{
    ++count;
}
while (count < 10);
```

The semicolon after the `while` condition is required.

---

## `break`

Terminates the nearest enclosing loop or `switch`.

```cpp
for (int i = 0; i < 10; ++i)
{
    if (i == 5)
    {
        break;
    }
}
```

---

## `continue`

Skips to the next iteration of the nearest enclosing loop.

```cpp
for (int i = 0; i < 10; ++i)
{
    if (i % 2 == 0)
    {
        continue;
    }

    std::cout << i;
}
```

---

## `goto`

Transfers control to a label.

```cpp
goto finish;

std::cout << "Skipped";

finish:
std::cout << "Done";
```

`goto` is valid C++, but structured control flow is generally easier to maintain.

---

## `return`

Returns from a function.

```cpp
int add(int a, int b)
{
    return a + b;
}
```

For a `void` function:

```cpp
void print()
{
    return;
}
```

---

# 5.3.5 Class-Related Keywords

Important class/object-oriented keywords include:

```text
class
struct
union
public
private
protected
friend
this
virtual
explicit
mutable
```

---

## `class`

Defines a class type.

```cpp
class Student
{
public:
    int age;
};
```

By default, members of a `class` are private.

---

## `struct`

Defines a class-like type whose members are public by default.

```cpp
struct Point
{
    int x;
    int y;
};
```

Compare:

```cpp
class A
{
    int x;       // private by default
};

struct B
{
    int x;       // public by default
};
```

Both `class` and `struct` can have:

- Data members
- Member functions
- Constructors
- Destructors
- Access control
- Inheritance
- Templates
- Static members
- Virtual functions

The key default difference is access control.

---

## `union`

Defines a union type in which members share storage.

```cpp
union Data
{
    int i;
    float f;
};
```

Only one member's stored value should generally be treated as active at a time according to the language rules.

---

## `public`

Members after `public:` are publicly accessible.

```cpp
class Student
{
public:
    void print();
};
```

---

## `private`

Members after `private:` are accessible according to the class's access rules.

```cpp
class Student
{
private:
    int age;
};
```

---

## `protected`

Members after `protected:` are accessible to the class and appropriate derived classes/friends according to C++ access rules.

```cpp
class Base
{
protected:
    int value;
};
```

---

## `friend`

A friend declaration gives a specified function or class access privileges.

```cpp
class Box
{
private:
    int value;

    friend void show(const Box&);
};
```

---

## `this`

Inside a non-static member function, `this` represents the current object.

```cpp
class Student
{
private:
    int age;

public:
    void setAge(int age)
    {
        this->age = age;
    }
};
```

Here:

```text
this->age
```

refers to the data member.

---

## `virtual`

Used for virtual functions and runtime polymorphism.

```cpp
class Base
{
public:
    virtual void print()
    {
        std::cout << "Base";
    }
};
```

---

## `explicit`

Prevents certain unwanted implicit conversions for constructors and conversion functions.

```cpp
class Number
{
public:
    explicit Number(int value)
    {
    }
};
```

Then:

```cpp
Number n(10);      // OK
Number m = 10;     // Not allowed because constructor is explicit
```

---

## `mutable`

Allows a data member to be modified even through a `const` object in permitted circumstances.

```cpp
class Counter
{
    mutable int calls = 0;

public:
    void print() const
    {
        ++calls;
    }
};
```

---

# 5.3.6 Template-Related Keywords

Important template-related language elements include:

```text
template
typename
class
requires
concept
```

---

## `template`

Introduces a template declaration.

```cpp
template <typename T>
T add(T a, T b)
{
    return a + b;
}
```

The function can be instantiated for different suitable types.

Example:

```cpp
int a = add(10, 20);
double b = add(1.5, 2.5);
```

---

## `typename`

Used to declare a template type parameter:

```cpp
template <typename T>
void print(T value)
{
    std::cout << value;
}
```

`class` can also be used for a type template parameter:

```cpp
template <class T>
void print(T value)
{
}
```

For this use, `typename` and `class` are generally equivalent.

### `typename` and dependent names

`typename` also tells the compiler that a dependent qualified name represents a type:

```cpp
template <typename T>
void function()
{
    typename T::value_type value{};
}
```

Without `typename`, the parser cannot generally assume that `T::value_type` is a type.

---

## `requires`

C++20 introduced constraints.

Example:

```cpp
template <typename T>
requires std::integral<T>
T add(T a, T b)
{
    return a + b;
}
```

The template is constrained to suitable integral types.

---

## `concept`

A concept gives a name to a set of requirements.

```cpp
template <typename T>
concept Number =
    std::integral<T> ||
    std::floating_point<T>;
```

Then:

```cpp
template <Number T>
T add(T a, T b)
{
    return a + b;
}
```

Concepts improve template diagnostics and express template requirements more clearly.

---

## `export`

`export` is associated with templates/modules depending on the language feature and standard version.

Modern C++20 modules use forms such as:

```cpp
export module math;
```

and:

```cpp
export int add(int a, int b);
```

---

# 5.3.7 Exception-Related Keywords

The main exception-handling keywords are:

```text
try
catch
throw
noexcept
```

---

## `try`

Marks a block containing code that may throw.

```cpp
try
{
    riskyOperation();
}
```

---

## `catch`

Handles an exception.

```cpp
try
{
    riskyOperation();
}
catch (const std::exception& e)
{
    std::cout << e.what();
}
```

---

## `throw`

Throws an exception.

```cpp
throw std::runtime_error("Operation failed");
```

A `throw` expression transfers control to an appropriate handler.

---

## `noexcept`

Specifies an exception specification.

```cpp
void process() noexcept
{
}
```

It can also be conditional:

```cpp
template <typename T>
void process(T& value)
    noexcept(noexcept(value.process()))
{
    value.process();
}
```

The inner:

```cpp
noexcept(expression)
```

can test whether an expression is non-throwing.

---

# 5.3.8 Modern C++ Keywords

Modern C++ introduced many useful keywords.

---

## `auto`

Performs type deduction.

```cpp
auto age = 25;
auto price = 99.99;
```

The compiler deduces the type from the initializer.

```cpp
auto name = std::string("Deep");
```

`auto` does not mean "dynamically typed". The type is still determined at compile time.

---

## `decltype`

Obtains the type category associated with an expression.

```cpp
int x = 10;
decltype(x) y = 20;
```

Here `decltype(x)` is `int`.

`decltype` follows special rules depending on whether its operand is an unparenthesized id-expression, member access, or another expression.

Example:

```cpp
int x = 10;

decltype(x) a = 20;      // int
decltype((x)) b = x;     // int&
```

This distinction is important in advanced C++.

---

## `constexpr`

Used for constant expressions and compile-time-capable functions/objects.

```cpp
constexpr int size = 100;
```

Example:

```cpp
constexpr int square(int x)
{
    return x * x;
}
```

A `constexpr` function can be evaluated at compile time when its call and arguments satisfy constant-expression requirements.

---

## `consteval`

Introduced in C++20.

It declares an **immediate function**.

```cpp
consteval int square(int x)
{
    return x * x;
}
```

A call to an immediate function generally must be evaluated at compile time.

---

## `constinit`

Introduced in C++20.

It requires constant initialization for a variable with static or thread storage duration.

```cpp
constinit int globalValue = 100;
```

`constinit` does not make the object itself `const`.

For example, an object declared with `constinit` may still be modified later if its type is non-const.

---

## `nullptr`

Represents the null pointer value.

```cpp
int* ptr = nullptr;
```

Prefer:

```cpp
nullptr
```

over:

```cpp
NULL
```

or:

```cpp
0
```

when expressing a null pointer.

`nullptr` has a dedicated null pointer type and avoids many overload-resolution problems associated with integer `0` or macro-based `NULL`.

---

## `static_assert`

Performs a compile-time assertion.

```cpp
static_assert(sizeof(int) >= 2);
```

With a message:

```cpp
static_assert(sizeof(int) >= 2,
              "int does not meet the required size");
```

If the condition is false when it must be evaluated, compilation fails.

---

## `thread_local`

Specifies thread storage duration.

```cpp
thread_local int counter = 0;
```

Each thread gets its own instance of the variable.

---

## `using`

Can introduce type aliases.

```cpp
using Integer = int;

Integer value = 10;
```

It can also introduce declarations:

```cpp
using std::cout;
```

and namespace aliases can be created with `using`:

```cpp
namespace fs = std::filesystem;
```

The latter is a namespace alias declaration.

---

## `alignas`

Specifies alignment requirements.

```cpp
struct alignas(16) Data
{
    int value;
};
```

---

## `alignof`

Queries the alignment requirement of a type.

```cpp
std::size_t alignment = alignof(Data);
```

---

## `co_await`, `co_yield`, `co_return`

These are associated with C++ coroutines.

Example:

```cpp
co_return value;
```

A coroutine uses special language machinery to suspend and resume execution.

These keywords are important in modern asynchronous/generator-style C++ but are usually studied after basic functions, classes, and templates.

---

# 5.3.9 Contextual Keywords

Not every word that behaves specially in C++ is an ordinary keyword in every grammatical context.

Some words are **contextual keywords**: their special meaning depends on where they appear.

Examples include:

```text
override
final
import
module
```

For example:

```cpp
class Base
{
public:
    virtual void print();
};

class Derived : public Base
{
public:
    void print() override;
};
```

`override` has special meaning in this context.

Similarly:

```cpp
class Base
{
public:
    virtual void print() final;
};
```

`final` indicates that further overriding is not permitted for that virtual function.

### Why contextual keywords exist

C++ has a huge amount of existing source code. Making every newly introduced language word a universally reserved keyword could break older programs.

Contextual keywords allow the language to introduce syntax while reducing unnecessary name conflicts.

# 5.4.1 `;` — Semicolon


## Expression statement

```cpp
age = 25;
```

---

## Function return

```cpp
return age;
```

## Empty statement

A standalone semicolon is an empty statement:

```cpp
;
```

It is legal, although usually not useful.

### Common error

Incorrect:

```cpp
int x = 10
```

Correct:

```cpp
int x = 10;
```

Missing a required semicolon can produce compiler errors at a later-looking line because the parser may not recognize where the previous statement ended.

# 5.4.2 `,` — Comma

The comma is used to separate items in many syntactic constructs.

---

## Multiple declarations

```cpp
int a = 10, b = 20, c = 30;
```

---

## Function arguments

```cpp
add(a, b);
```

---

## Function parameters

```cpp
int add(int a, int b)
{
    return a + b;
}
```

---

## Initializer lists

```cpp
int values[] = {10, 20, 30};
```

---

## Template arguments

```cpp
std::pair<int, double>
```

The comma separates:

```text
int
double
```

---

## Comma operator

The comma can also be an operator.

```cpp
int x;

x = (x = 10, x + 5);
```

The comma operator evaluates the left operand, then the right operand, and the result is the value/category of the right operand.

Do not confuse:

```cpp
add(a, b)
```

with a comma-operator expression in every context. In a function argument list, the comma primarily separates arguments.

---

# 5.4.3 `.` — Dot

The dot is used for member access through an object expression.

```cpp
object.member
```

Example:

```cpp
struct Student
{
    int age;
};

Student s;
s.age = 20;
```

Here:

```cpp
s.age
```

accesses the `age` member of `s`.

---

## Chained member access

```cpp
object.member.function();
```

Example:

```cpp
student.getName().size();
```

Each dot can access a member of the preceding object/expression.

---

# 5.4.4 `->` — Arrow

The arrow operator accesses a member through a pointer.

```cpp
pointer->member
```

Example:

```cpp
Student s;
Student* ptr = &s;

ptr->age = 20;
```

Conceptually:

```cpp
ptr->age
```

is equivalent to:

```cpp
(*ptr).age
```

### Why parentheses?

Because:

```cpp
*ptr.age
```

would be interpreted differently due to operator precedence.

The correct expanded form is:

```cpp
(*ptr).age
```

---

## Arrow with member functions

```cpp
ptr->print();
```

This calls the member function through the pointer.

---

# 5.4.5 `::` — Scope Resolution


Here:

```text

```

is a namespace and:

```text

vector
```

are names within it.

## Class member definition

```cpp
    void print();

}
```

The:

```cpp
Student::print
```

notation means `print` belongs to `Student`.

## Nested scope

```cpp
Outer::Inner
```

can refer to a name nested within another scope.

---

## Global scope

```cpp

{
```

`::value` refers to the global-scope declaration.

The colon has several uses.

## `case`

## `default`

```cpp

    std::cout << "Other";
```

---

## Inheritance

```cpp

};
```

The colon introduces the base-specifier list.

## Constructor initializer list

```cpp
class Student
{
private:
    int age;

public:
    Student(int value)

    {
    }
```

Here:


## Conditional operator

# 5.4.7 `?` — Question Mark

The question mark participates in the conditional operator:

```cpp
condition ? expression1 : expression2
```

Example:

```cpp
int maxValue = (a > b) ? a : b;
```

Meaning:

```text
if a > b:
    maxValue = a
else:
    maxValue = b
```

### Important

The conditional operator is an **expression**, so it produces a result.

Example:

```cpp
int result = condition ? 100 : 200;
```

---

## Nested conditional operator

It is possible but can become difficult to read:

```cpp
int result =
    a > b ? 1 :
    b > c ? 2 :
            3;
```

For complex logic, ordinary `if`/`else` is often clearer.

# 5.5 Other Important Lexical Elements

The requested token categories are the main focus, but several related lexical concepts are essential for understanding C++ source code.

---

# 5.5.1 Comments

Comments document source code and are not treated as executable statements.

C++ supports two main comment forms.

## Single-line comment

```cpp
// This is a comment
int age = 25;
```

The comment continues to the end of the source line.

---

## Multi-line comment

```cpp
/*
    This is a
    multi-line comment.
*/
int age = 25;
```

---

## Comments can explain code

```cpp
int total = price * quantity; // Calculate total price
```

Good comments explain **why**, not merely what obvious code does.

Avoid:

```cpp
i++; // Increment i
```

when the code itself already makes the meaning obvious.

---

## Comments and tokenization

Comments are removed/handled during translation before they become ordinary program tokens. They do not become executable C++ statements.

---

# 5.5.2 Whitespace

Whitespace includes source formatting characters such as:

- Spaces
- Tabs
- Newlines

Example:

```cpp
int x = 10;
```

and:

```cpp
int    x    =    10;
```

usually represent the same token sequence in this context.

Whitespace is important for separating tokens.

For example:

```cpp
int value;
```

contains separate lexical elements:

```text
int
value
```

rather than one combined identifier.

### Newlines

Newlines generally do not terminate C++ statements.

This is valid:

```cpp
int x =
    10;
```

The semicolon determines the statement termination.

---

# 5.5.3 Preprocessing

Before the compiler parses the complete C++ program, preprocessing-related steps handle directives such as:

```cpp
#include <iostream>
#define SIZE 100
#if defined(DEBUG)
#endif
```

A preprocessing directive begins with `#` in the appropriate source context.

Example:

```cpp
#include <iostream>
```

The `<iostream>` portion in an include directive is not simply the same thing as a normal template argument list.

This is an important example of why the meaning of characters depends on context.

---

## Macro example

```cpp
#define MAX_SIZE 100
```

The macro name:

```text
MAX_SIZE
```

is a preprocessing identifier.

Macros are processed by the preprocessor and can affect the token stream before normal compilation.

Modern C++ often prefers:

```cpp
constexpr int maxSize = 100;
```

when a macro is not required.

---

# 5.5.4 Stringizing and Token Pasting

The preprocessor has special operators used in macro definitions.

## `#` stringizing

Example:

```cpp
#define TO_STRING(x) #x
```

Then:

```cpp
TO_STRING(hello)
```

produces a string literal corresponding to the spelling of the argument.

---

## `##` token pasting

Example:

```cpp
#define MAKE_NAME(a, b) a##b
```

Then:

```cpp
MAKE_NAME(value, 1)
```

can form the preprocessing token:

```text
value1
```

These are preprocessing operators and should not be confused with ordinary runtime operators.

---

# 5.5.5 Alternative Operator Representations

C++ provides alternative textual representations for several operators.

| Symbol | Alternative token |
|---|---|
| `&&` | `and` |
| `||` | `or` |
| `!` | `not` |
| `!=` | `not_eq` |
| `&` | `bitand` |
| `|` | `bitor` |
| `^` | `xor` |
| `~` | `compl` |
| `&=` | `and_eq` |
| `|=` | `or_eq` |
| `^=` | `xor_eq` |

Example:

```cpp
if (a and b)
{
}
```

is equivalent in meaning to:

```cpp
if (a && b)
{
}
```

These alternative spellings are part of the C++ language.

# 5.7 Common Mistakes

## Mistake 1 — Starting an identifier with a digit

Wrong:

```cpp
int 123value = 10;
```

Correct:

```cpp
int value123 = 10;
```

---

## Mistake 2 — Using a keyword as a variable

Wrong:

```cpp
int class = 10;
```

Correct:

```cpp
int classCount = 10;
```

---

## Mistake 3 — Forgetting case sensitivity

Wrong:

```cpp
int studentAge = 20;

std::cout << studentage;
```

Correct:

```cpp
std::cout << studentAge;
```

---

## Mistake 4 — Confusing `.` and `->`

Object:

```cpp
Student s;
s.print();
```

Pointer:

```cpp
Student* p = &s;
p->print();
```

---

## Mistake 5 — Confusing `::` and `.`

Namespace/class scope:

```cpp
std::cout
Student::print
```

Object member:

```cpp
student.print()
```

---

## Mistake 6 — Missing semicolon

Wrong:

```cpp
int age = 25
```

Correct:

```cpp
int age = 25;
```

---

## Mistake 7 — Confusing `=` and `==`

Assignment:

```cpp
x = 10;
```

Equality comparison:

```cpp
if (x == 10)
{
}
```

---

## Mistake 8 — Confusing `&&` and `&`

Logical AND:

```cpp
if (a && b)
{
}
```

Bitwise AND:

```cpp
int result = a & b;
```

They have different meanings.

---

## Mistake 9 — Confusing `||` and `|`

Logical OR:

```cpp
if (a || b)
{
}
```

Bitwise OR:

```cpp
int result = a | b;
```

---

## Mistake 10 — Using reserved identifiers

Avoid:

```cpp
__value
_Foo
```

Use:

```cpp
value
fooValue
```

# 5.9 Interview and Exam Questions

## Q1. What is a token in C++?

A token is a basic lexical unit recognized by the C++ language implementation. Important categories include keywords, identifiers, literals, operators, and punctuators.

---

## Q2. What are the main token categories?

For this chapter:

```text
Keywords
Identifiers
Literals
Operators
Punctuators
```

---

## Q3. Is C++ case-sensitive?

Yes.

```cpp
value
Value
VALUE
```

are different identifiers.

---

## Q4. Can an identifier start with a number?

No.

Invalid:

```cpp
1value
```

Valid:

```cpp
value1
```

---

## Q5. Can a keyword be used as an identifier?

Normally no.

Invalid:

```cpp
int class = 10;
```

---

## Q6. What is the difference between `.` and `->`?

`.` accesses a member through an object/expression.

```cpp
object.member;
```

`->` accesses a member through a pointer.

```cpp
pointer->member;
```

---

## Q7. What does `::` mean?

It is the scope resolution operator.

Examples:

```cpp
std::cout
Student::print
::globalValue
```

---

## Q8. What is `nullptr`?

`nullptr` represents the null pointer value and is preferred over integer `0` or `NULL` for null pointer expressions.

---

## Q9. What is `auto`?

`auto` requests type deduction from an initializer.

```cpp
auto value = 10;
```

The compiler deduces `value` as an appropriate integer type based on the initializer.

---

## Q10. What is `constexpr`?

`constexpr` marks an entity/function as capable of participating in constant evaluation when its use satisfies the relevant constant-expression rules.

Example:

```cpp
constexpr int square(int x)
{
    return x * x;
}
```

---

## Q11. What is the difference between `class` and `struct`?

Both define class types.

The primary default difference is access:

```cpp
class A
{
    int x;  // private
};

struct B
{
    int x;  // public
};
```

Their inheritance defaults also differ:

- `class` defaults to private inheritance.
- `struct` defaults to public inheritance.

---

## Q12. What is a punctuator?

A punctuator is a lexical symbol used to provide syntactic structure.

Examples:

```cpp
;
,
()
[]
{}
::
```

---

## Q13. What is the difference between a keyword and an identifier?

A keyword has a predefined meaning in the C++ language:

```cpp
int
class
return
```

An identifier is a programmer-defined name:

```cpp
age
Student
calculateTotal
```

---

## Q14. What is a literal?

A literal is a value written directly in source code.

Examples:

```cpp
10
3.14
'A'
"Hello"
true
nullptr
```

---

## Q15. Is `else if` one keyword?

No.

It is two keywords:

```text
else
if
```

---

# 5.10 Final Mental Model

When reading C++ code, try to classify each piece.

Example:

```cpp
class Student
{
public:
    int age;

    void print()
    {
        std::cout << age;
    }
};
```

Think:

```text
class       -> keyword
Student     -> identifier
{           -> punctuator
public      -> keyword
:           -> punctuator
int         -> type keyword
age         -> identifier
;           -> punctuator
void        -> type keyword
print       -> identifier
(           -> punctuator
)           -> punctuator
{           -> punctuator
std         -> name/identifier
::          -> scope-resolution punctuator
cout        -> name/identifier
<<          -> operator
age         -> identifier
;           -> punctuator
}           -> punctuator
}           -> punctuator
;           -> punctuator
```

This gives you a powerful way to read unfamiliar C++ syntax.

# 5.11 Chapter Summary

C++ source code is made from lexical elements that are recognized and processed by the language implementation.

The five important categories covered here are:

```text
1. Keywords
2. Identifiers
3. Literals
4. Operators
5. Punctuators
```

### Keywords

Reserved language words:

```cpp
int
class
if
return
template
```

### Identifiers

Programmer-defined names:

```cpp
age
Student
calculateTotal
```

### Literals

Values written directly in source code:

```cpp
10
3.14
'A'
"Hello"
true
nullptr
```

### Operators

Symbols/keywords that perform operations:

```cpp
+
-
*
/
=
==
&&
||
```

### Punctuators

Symbols that structure syntax:

```cpp
;
,
.
->
::
:
?
()
[]
{}
<>
```

The most important practical rules are:

1. **C++ identifiers are case-sensitive.**
2. **Identifiers cannot start with digits.**
3. **Keywords cannot normally be used as identifiers.**
4. **Avoid implementation-reserved identifier patterns.**
5. **Use `.` for member access through an object and `->` through a pointer.**
6. **Use `::` for scope resolution.**
7. **Use `;` to terminate statements where required.**
8. **Use `nullptr` for null pointer values.**
9. **Use modern C++ features such as `auto`, `constexpr`, concepts, and `nullptr` appropriately.**
10. **Always distinguish syntax rules from naming/style conventions.**

Understanding tokens provides the foundation for the next levels of C++ syntax: expressions, declarations, statements, functions, classes, templates, and the type system.
